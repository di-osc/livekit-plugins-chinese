每个服务商都是独立 Python 包，只安装业务实际需要的插件即可。

## 从 PyPI 安装 {id="pypi"}

```bash
pip install livekit-plugins-aliyun
pip install livekit-plugins-volcengine
pip install livekit-plugins-stepfun
pip install livekit-plugins-difyai
pip install livekit-plugins-flashtts
```

如果项目使用 `uv`：

```bash
uv add livekit-plugins-aliyun
```

<Infobox title="Dify 的包名" variant="warning">

Dify 在 PyPI 上的安装包名是 `livekit-plugins-difyai`，Python 导入名仍是
`from livekit.plugins import dify`。

</Infobox>

## 从源码安装 {id="source"}

本仓库使用 uv workspace。不要新建虚拟环境，直接在仓库现有环境同步依赖：

```bash
cd /path/to/livekit-plugins-chinese
uv sync
```

只以可编辑方式安装某个插件：

```bash
uv pip install -e livekit-plugins/livekit-plugins-aliyun
```

## 确认版本 {id="verify"}

```bash
python -c "import livekit.agents; print(livekit.agents.__version__)"
python -c "from livekit.plugins import aliyun; print(aliyun.__version__)"
```

运行 Agent 时，日志中也会打印 Agents、RTC 和已注册插件的版本。

## 更新依赖 {id="upgrade"}

发布包当前固定依赖 `livekit-agents==1.6.7`。升级 LiveKit 前应先在独立分支更新所有
插件的版本约束并执行完整测试，尤其要验证 Realtime 事件、工具调用和打断行为，避免
只升级主包后出现接口不兼容。
